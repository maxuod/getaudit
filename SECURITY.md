# Security and private research data

This is an early-access source project. Supported binary release versions have not been announced.

Do not put credentials, account identifiers, cookies, private links, answer captures, customer records, or analytics data in public issues or pull requests. Reproduce problems using reserved example domains and synthetic data.

If a public repository later enables private vulnerability reporting, use that channel for security reports. Do not post an exploit or private data to a public issue while no private reporting channel is available.

Review every outgoing file, including screenshots, generated reports, metadata, Git history, and dependency notices. Ignore rules and automated secret checks cannot prove the absence of confidential information. If a real credential has ever been shared, remove the exposure and rotate it with its provider; deleting a file does not revoke a credential.
